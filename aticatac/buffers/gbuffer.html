Address Length Description
5E00 1
Game Options
Byte Binary Character Option
00 00000000 Knight Keyboard
02 00000010 Knight Kempston Joystick
04 00000100 Knight Cursor Joystick
08 00001000 Wizard Keyboard
0A 00001010 Wizard Kempston Joystick
0C 00001100 Wizard Cursor Joystick
10 00010000 Serf Keyboard
12 00010010 Serf Kempston Joystick
14 00010100 Serf Cursor Joystick
5E01 2
Font Pointer
Holds a pointer to the currently used font data.
5E03 1
Last Frame
The low byte of FRAMES as it was when UpdateFixedEntities last ran. The main loop compares it with FRAMES to find out whether a new frame has started.
5E04 1
In Handlers
Set to 01 while UpdateFixedEntities runs the handlers of the fixed entities, and set back to 00 when it has finished. Nothing in the game reads it.
5E05 2
Random Seed
A random number seed. At the end of every pass through DrawRoom the value of FRAMES and the low byte of the counter at CounterLow are added to it. The low byte is tested by HandlerTrapOpen to decide whether an open trapdoor closes.
5E10 1
Sprite Width
The width in bytes of the sprite that is being drawn or removed, or of the item whose attribute cells are being set. It is 02 when the sprite starts on a multiple of eight pixels across, and 03 when it does not, as the sprite then covers a third byte once it has been shifted.
5E11 1
Sprite Height
The height in pixel rows of the sprite that is being drawn or removed, or of the item whose attribute cells are being set (10 for the items that can be picked up).
5E12 1
Counter Low
The low byte of a 16-bit counter that is increased by DrawRoom at the end of every pass through the main loop. The handlers use it to make things happen on every other pass (bit 0), and to choose the frames of animations.
5E13 1
Counter High
The high byte of the counter that is held in CounterLow. SpawnFood tests bit 0 of it, and SetKeyPositions adds it to FRAMES to choose the room of the cyan key.
5E14 1
Game Flags
Bit 0 is set by DrawRoom once the entities in the room have been drawn, and is reset by DrawRoomFrame when a new room is going to be drawn. The items in the room are only drawn (see HandlerRoomItem) while it is zero. The game does not use any of the other bits.
5E15 1
Previous Sprite Id
The sprite ID of the entity that was last stored by StoreEntity or SetEntityAttributes. GetSpriteA uses it to find the old sprite to erase, and LoseLife uses it to put the player back after a life has been lost.
5E16 1
Previous X Position
The X position of the entity that was last stored by StoreEntity or SetEntityAttributes.
5E17 1
Previous Y Position
The Y position of the entity that was last stored by StoreEntity or SetEntityAttributes.
5E18 1
Old Sprite Row Count
The number of rows of the old sprite that are left to be drawn (erased) when the rows that overlap with the new sprite have been done. See XORSpriteLoop.
5E19 1
New Sprite Row Count
The number of rows of the new sprite that are left to be drawn when the rows that overlap with the old sprite have been done. See XORSpriteLoop.
5E1A 1
Room Attribute
The attribute of the floor of the current room, which is read from the room attribute table by DrawRoomFrame. It is the attribute that SetEntityAttributes_Moved gives to the cells that an entity has left behind.
5E1B 2
Room Pointer
The address of the next item to look at in the list of items for the current room (see RoomTable). DrawRoom sets it to the start of the list and moves it on by two bytes for each item.
5E1D 1
Room Width
The width of the floor of the current room, written by DrawRoomFrame from the shape of the room. It is stored just before the height, so that routines can read both with one DE or HL load.
5E1E 1
Room Height
The height of the floor of the current room, written by DrawRoomFrame from the shape of the room.
5E1F 1
Pickup Flags
Stops a single press of the pick up key from picking up or dropping more than one item. Bits 0-1 are set by HandlerPickupItem when an item is picked up, and bit 1 is set by HandlerBlank when the inventory is dropped. While either bit is set the key does nothing. Bit 1 is reset by ClearPickupFlag and HandlerBlank_KeyUp when the key is not pressed, and bit 0 is reset by HandlerBlank_Finish.
5E20 1
Pickup Pressed
Set to 02 while the pick up key is pressed, and to 00 when it is not. It is written by ReadPickupKey.
5E21 1
Lives
The number of lives that the player has left. It starts at 03 (see StartGame), and is decreased by LoseLife when a life is lost.
5E22 1
Menu Item Attribute
The attribute of the line of text that MenuWriteText is printing on the game selection screen. GameMenu_Loop copies it from the table of attributes at GameSelection_Attributes.
5E23 1
Line Distance
The longer of the two distances of the line that DrawLine is drawing (the distance across or the distance up or down). One more than this is the number of steps that are taken.
5E24 1
Line Flags
The direction of the line that DrawLine is drawing. Bit 0 is set if the line goes down, and bit 1 is set if it goes right.
5E25 1
Number Creatures
Number of creatures processed this frame.
5E26 1
Last Creature Room
The room that the player was in when SpawnCreature last started the delay before a creature is created.
5E27 1
Creature Delay
The number of passes that SpawnCreature waits before it starts to create creatures in a room. It is set to 20 when the player enters a new room, and counted down while the player stays in it.
5E28 1
Player Energy
The energy of the player, which is shown as the chicken at the side of the screen. It starts at F0 (see PreparePlayer_Energy). It is decreased when the player is hurt (see HurtPlayer) and increased by eating food (see HandlerFoodItem). When it reaches zero a life is lost.
5E29 1
Chicken Level
The energy that was last drawn as the chicken, so that DrawChicken only redraws it when the energy has changed enough to make a difference.
5E2A 3
Score
The score, which is six decimal digits held as three bytes of BCD. The most significant byte is first. AddPointsToScore adds to it and Score_1UP prints it.
5E2D 1
In Doorway
The number of axes on which the player is outside the floor of the room, as counted by CheckDoorway. It is zero when the player is not in a doorway.
5E2E 1
Door Timer
The time left before the doors that open and close (see HandlerDoorOpen and HandlerDoorClosed) change. It is counted down every other pass, and set to 5E when they change.
5E2F 1
Walk Counter
Counts the footsteps of the player. SoundsWalking increases it on every call and uses it to alternate the sound.
5E30 4
Inventory 1
The slot of the inventory for the item that has been carried for the shortest time. A slot is the address of the entity of the item (two bytes, low byte first, or 00 if the slot is empty), then the sprite ID and the attribute of the item.
5E34 4
Inventory 2
The slot of the inventory for the item that has been carried for the second shortest time. A slot is the address of the entity of the item (two bytes, low byte first, or 00 if the slot is empty), then the sprite ID and the attribute of the item.
5E38 4
Inventory 3
The slot of the inventory for the item that has been carried for the longest time. A slot is the address of the entity of the item (two bytes, low byte first, or 00 if the slot is empty), then the sprite ID and the attribute of the item.
5E3C 1
Flash Timer
The time left before the player starts to appear at the start of a life. PreparePlayer sets it to 68 and FlashScore counts it down (see HandlerPlayerAppearing) while the score flashes.
5E3D 1
Clock Hours
The hours of the clock that is shown at the top of the screen, as BCD. See ClockTick.
5E3E 1
Clock Minutes
The minutes of the clock that is shown at the top of the screen, as BCD. See ClockTick.
5E3F 1
Clock Seconds
The seconds of the clock that is shown at the top of the screen, as BCD. See ClockTick.
5E40 20
Visited Rooms
One bit for each room, set by VisitRoom when the player has been in it. There are 08 rooms to a byte, so the bit for a room is bit (room MOD 08) of byte (room / 08). CalculateRoomsVisited counts the bits.
5E54 1
Visited Percentage
The percentage of the rooms that the player has visited, as BCD. It is calculated by CalculateRoomsVisited and shown by GameStats.
5E55 2
Food Pointer
The address of the entity that SpawnFood will look at next, to see whether it can be made into a food item. It starts at FoodItems (see 7DA2).
600D 8
Player Initialisation Data
The entity for the player, which is copied to Player when the game is reset (see ResetGameState). It is all zero because PreparePlayer sets it up from the template at PlayerTemplate at the start of each life. Player describes the layout of an entity.
6015 8
Weapon Initialisation Data
The entity for the weapon that the player throws, which is copied to PlayerWeapon. The weapon is a 16-byte record, and the sound entity that follows is its second half. The flags are at offset 02 and the velocities are at offsets 06 and 07 and the lifetime is at offset 0F (see SetWeaponVelocity). The sprite ID is zero while the weapon is not in use.
601D 8
Sound Initialisation Data
The entity for the sound effects, which is copied to PlayerWeapon_Sound. The first byte is the handler of the sound and the second byte is the count of notes left to play (see QueueSound). Both are zero when there is no sound. The last byte of it is the lifetime of the weapon.

645D 16
Door: 07 / 00
The doorway between the top wall of room 07 and the bottom wall of room 00. Doors are made of two 8-byte room items, one in each of the rooms that they join, which are the two halves of the door (see GetOtherDoorHalf). Each half is in the list of items for its room (see RoomTable). The other doors, and the other pairs of items that follow, are laid out in the same way.
Offset Description
00 Graphic ID (also the index of the handler in HandlerTable2)
01 Room ID
02 Exit offsets
03 X position
04 Y position
05 Attribute (bits 5-7 are the orientation, see DrawGraphic)
06 Obstacle X
07 Obstacle Y
The exit offsets are used by EnterDoor to put the player to the right of, and above, the position of the half that they come out of: the number of pixels to the right is twice the bottom four bits, and the number of pixels above is twice the top four bits. CheckObstacles uses the two obstacle bytes to make a rectangle, as long as bit 3 of the attribute is reset. An entity in the rectangle is blocked if bit 2 of the attribute is set, and is not blocked if it is reset. The left edge is in the top four bits of the X byte, and the top edge is in the top four bits of the Y byte (both signed). The width and height are in the bottom four bits of each. They are all in units of four pixels.

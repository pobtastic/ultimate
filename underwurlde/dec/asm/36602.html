36602: Object Records
Nineteen records of 16 bytes each. Run_Game works through them one by one, using byte 0 of each record (the type of the object, which is also its sprite id) as an index into the handler table at Object_Handler_Table. A type of 0 marks a record that is not in use.
The first two records are the weapons that Sabreman throws. They are handled only as priority records (see Finish_Object_Pass). The third record is Sabreman. Reset_Sabreman fills it in using the template at Sabreman_Template.
Some of the other records have fixed uses: the fourth is the rope (type 23 which Set_Up_Rope sets up when the room has a rope) and the fifth is a falling stalactite (see Spawn_Falling_Stalactite).
Byte Contents
0 Type of the object (the sprite id)
1 X position
2 Room x
3 Y position
4 Room y
5 Attribute
6-15 Used differently by each type of handler
Most handlers use bit 0 of byte 15 (or of byte 7) as a flag to say that the sprite has no old image to erase (see Update_Object_Sprite). Byte 9 is often a vertical speed and bytes 10 and 13 are often the fractions of the x and y positions.
